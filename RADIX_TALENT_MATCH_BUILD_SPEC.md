## 1. What this project is

A single Python + Streamlit application that answers one question for a candidate:

> "Am I actually ready for this job, and if not, what exactly is missing?"

It does this through five modules that pass JSON to each other:

```
JD file ──────────► [1] JD Analytics ──────► jd_skills.json ─┐
                                                              │
Resume file ──────► [2] Resume Parsing ───► resume_skills.json│
                            │                                 │
                            ▼                                 │
                    [3] Profile Builder ──► profile.json ──┬──┘
                                                           │
                            ┌──────────────────────────────┤
                            ▼                              ▼
                  [4] Talent Check              [5] Skill Matching
              (profile vs COMPANY bar)        (profile vs ONE JD)
                            │                              │
                            ▼                              ▼
               talent_check_result.json      skill_match_result.json
```

**The critical distinction — do not blur these:**

- **Module 4 (Talent Check)** compares the candidate against a **company's general hiring bar** across all 12 skillsets. Its reference data is the company skillset CSV. It answers *"could I get into Microsoft?"*
- **Module 5 (Skill Matching)** compares the candidate against **one specific job posting**. Its reference data is the extracted JD skill list. It answers *"do I fit this exact Data Analyst role?"*

Module 5 never reads the company CSV. Module 4 never reads a JD.

## 2. Architecture decisions (these are fixed — do not deviate)

| Decision | Choice | Reason |
|---|---|---|
| Language | Python 3.10+ | Matches the rest of RADIX |
| UI | Streamlit, single app, 5 tabs | Fastest path to a live demo; no React build step |
| Storage | Local JSON files in `data/` | No Supabase, no network dependency |
| Skill extraction | Deterministic keyword dictionary **first**, LLM as optional enhancement | Must run offline with zero API failures during the demo |
| Module boundaries | 5 separate Python files, each exposing one pure function | Any module can be swapped for a teammate's version |
| Integration | `pipeline.py` calls all 5 in order | Integration is designed in from minute one, not bolted on |

**Every module function takes plain Python data in and returns plain Python data out. No module writes files directly — only `storage.py` touches disk.** This is what makes the modules swappable and testable.

## 5. The company dataset — how to convert and use it

The provided CSV has 13 columns. Column 1 is `companies`. The other 12 map onto the 12 category codes.

Cells look like `8-AS`:
- The number before the dash is the **required level, 1–10**. This is what you score against.
- The letters after the dash are a **maturity band** (`CU`, `AP`, `AS`, `EV`). Display it as a label. **Never build scoring logic on the band** — it is metadata only.

### 5.1 `scripts/build_company_json.py`

```python
import csv, json, pathlib

COLUMN_TO_CODE = {
    "coding": "COD",
    "data_structures_and_algorithms": "DSA",
    "object_oriented_programming_and_design": "OOD",
    "aptitude_and_problem_solving": "APTI",
    "communication_skills": "COMM",
    "ai_native_engineering": "AI",
    "devops_and_cloud": "CLOUD",
    "sql_and_design": "SQL",
    "software_engineering": "SWE",
    "system_design_and_architecture": "SYSD",
    "computer_networking": "NETW",
    "operating_system": "OS",
}

SRC = pathlib.Path("data/skilll_levels_company.csv")
DST = pathlib.Path("data/talent_check_company_skillsets.json")

def main():
    out = {}
    with SRC.open(newline="", encoding="utf-8-sig") as f:
        for row in csv.DictReader(f):
            name = (row.get("companies") or "").strip()
            if not name or name in out:      # dataset contains duplicate rows — keep first
                continue
            skillsets = {}
            for col, code in COLUMN_TO_CODE.items():
                raw = (row.get(col) or "").strip()
                if not raw:
                    continue
                level, _, band = raw.partition("-")
                skillsets[code] = {
                    "required_level": int(level),
                    "band": band or "NA",
                    "raw": raw,
                }
            out[name] = {"company": name, "skillsets": skillsets}
    DST.parent.mkdir(parents=True, exist_ok=True)
    DST.write_text(json.dumps(out, indent=2))
    print(f"wrote {len(out)} companies to {DST}")

if __name__ == "__main__":
    main()
```

**Important notes about the dataset:**
- It contains duplicate company rows. Deduplicate by keeping the first occurrence.
- Company names are full legal names. The three in scope are exactly:
  - `Google LLC (Subsidiary of Alphabet Inc.)`
  - `Microsoft Corporation`
  - `Oracle Financial Services Software Limited`
- Some names contain commas and are quoted in the CSV. Use `csv.DictReader`, never `str.split(",")`.
- Roughly 98 unique companies survive deduplication. Expose all of them in the dropdown — it makes the demo look substantial.

Extraction function:

```python
def extract_skills(text: str, source_hint: str = "") -> list[dict]:
    """Scan text for keywords, return validated skill objects."""
```

Algorithm:
1. Lowercase the text.
2. For each category, for each keyword, count occurrences.
3. If count > 0, emit a skill object:
   - `skill_name` = the keyword, title-cased
   - `category_code` = the category
   - `evidence` = a ±60-character window around the first occurrence, whitespace-collapsed
   - `confidence` = `"high"` if count ≥ 3, `"medium"` if count == 2, `"low"` if count == 1
4. Deduplicate on `normalise_skill_name(skill_name)`, keeping the highest confidence.
5. Return sorted by category then name.

**Optional LLM enhancement — build only after everything else works.** Add `core/llm_extract.py` with the same signature. In `app.py`, put a sidebar checkbox "Use LLM extraction (slower)". Wrap the call in try/except and **fall back to the keyword extractor on any failure**. The demo must never depend on a network call.

## 7. Module specifications

### 7.1 `core/extract_text.py`

```python
def extract_text(path: str) -> str
```

- `.pdf` → `pypdf.PdfReader`, join `page.extract_text()` across pages
- `.docx` → `docx.Document`, join paragraph text plus all table cell text
- `.txt` / `.md` → read directly
- Anything else → raise `ValueError` with a readable message
- Never crash on one bad page: wrap per-page extraction in try/except and continue

Also expose:

```python
def guess_company_and_role(text: str, filename: str) -> tuple[str, str]
```

Simple heuristics: look for a known company name from the loaded JSON inside the first 2000 characters; look for common role titles (`Software Engineer`, `Data Scientist`, `Data Analyst`, `Associate Software Engineer`, `Application Support Analyst`). Fall back to parsing the filename. Whatever it guesses must be **editable in the UI** — never silently wrong.

### 7.2 `modules/m1_jd_analytics.py`

```python
def analyse_jd(text: str, source_file: str,
               company: str = "", role: str = "") -> dict
```

1. Focus the signal: if headings like *Key Responsibilities*, *What We're Looking For*, *Requirements*, *Qualifications* exist, extract those sections and weight them by concatenating them a second time onto the search text (a cheap way to boost their keyword counts and therefore their confidence).
2. Run `extract_skills`.
3. Assemble and return the §4.3 shape with `source_type: "jd"`.
4. Validate before returning.

### 7.3 `modules/m2_resume_parsing.py`

```python
def parse_resume(text: str, source_file: str) -> dict
```

1. Run `extract_skills` on the whole document.
2. Split the resume into sections by detecting heading lines (a short line, mostly uppercase or title case, no terminating period).
3. Populate `structured` with education, projects, experience, certifications from the matching sections. Missing section → empty list, never an exception.
4. Extract `candidate_name` from the first non-empty line; extract `email` with a regex.
5. Return the §4.3 shape with `source_type: "resume"` plus the extra keys.

Resumes are messy. Every extraction step must degrade gracefully rather than raise.

### 7.4 `modules/m3_profile_builder.py`

```python
def build_profile(form_data: dict, resume_payload: dict | None = None) -> dict
def prefill_from_resume(resume_payload: dict) -> dict
```

- `prefill_from_resume` maps a Module 2 output into form defaults.
- `build_profile` merges form input over the prefill, validates, and returns the §4.4 shape.
- Skills entered manually by the user get `confidence: "high"` and `evidence: "self-reported"`.
- Merging rule: if the same normalised skill appears from both resume and manual entry, keep one copy at the higher confidence.

### 7.5 `modules/m4_talent_check.py`

This is the scoring core. Get it exactly right.

```python
def estimate_candidate_levels(profile: dict) -> dict[str, int]
def run_talent_check(profile: dict, company: str, company_data: dict) -> dict
```

**Step A — estimate the candidate's level 1–10 per category.**

For each of the 12 categories, start at `0` and add:

| Signal | Points |
|---|---|
| At least one skill in this category exists | +4 |
| Any skill in this category has `confidence: "high"` | +2 |
| Any skill in this category has `confidence: "medium"` | +1 |
| ≥ 3 distinct skills in this category | +1 |
| A project, internship, or hackathon entry mentions a keyword from this category | +2 |
| A certification mentions a keyword from this category | +1 |

Cap at 10. A category with no evidence stays at 0.

The medium and high bonuses do not stack — take the maximum.

**Step B — compare against the company bar.**

```python
required = company_data[company]["skillsets"][code]["required_level"]
candidate = levels[code]
gap = candidate < required
gap_size = max(0, required - candidate)
```

**Step C — readiness score.**

```python
achieved = sum(min(candidate[c], required[c]) for c in CATEGORY_CODES)
total    = sum(required[c] for c in CATEGORY_CODES)
readiness_score = round(100 * achieved / total)
```

Credit is capped at the required level, so exceeding the bar in one area cannot mask a gap elsewhere. This is the correct behaviour — say so in the demo.

**Step D — verdict thresholds.**

```
>= 85  "Ready"
70-84  "Nearly ready"
50-69  "Developing"
< 50   "Significant gaps"
```

**Step E** — `top_gaps` is the three category codes with the largest `gap_size`, ties broken by higher `required_level`.

**Sanity check that must pass before you move on:** run the same company against two different sample resumes and confirm the scores differ by a visible margin. If they don't, the level estimator is broken.

### 7.6 `modules/m5_skill_matching.py`

```python
def match_skills(profile: dict, jd_payload: dict) -> dict
```

1. Build the profile's normalised skill set: `{normalised_name: original_skill_object}`.
2. For each JD skill:
   - **Exact match** on normalised name → record with `"how": "exact"`.
   - Otherwise **fuzzy match** using `difflib.get_close_matches(n=1, cutoff=0.85)` → record with `"how": "fuzzy"` and the `SequenceMatcher` ratio.
   - Otherwise → append to `missing_skills`.
3. Weight the score by confidence, because a JD's "high confidence" requirement matters more than a passing mention:

```python
WEIGHT = {"high": 3, "medium": 2, "low": 1}
earned   = sum(WEIGHT[s["confidence"]] for s in jd_skills if matched(s))
possible = sum(WEIGHT[s["confidence"]] for s in jd_skills)
match_score = round(100 * earned / possible) if possible else 0
```

4. `category_coverage` = for each category present in the JD, the fraction of that category's JD skills that were matched.
5. Sort `missing_skills` by confidence descending — highest-confidence gaps first. **The gap list is the point of this module; the number is secondary.**

If `jd_payload["skills"]` is empty, return `match_score: 0` with an explicit message rather than dividing by zero.

## 8. `pipeline.py`

```python
def run_pipeline(jd_path: str, resume_path: str, company: str,
                 profile_overrides: dict | None = None) -> dict
```

Executes:

1. `extract_text(jd_path)` → `analyse_jd(...)` → save `jd_skills.json`
2. `extract_text(resume_path)` → `parse_resume(...)` → save `resume_skills.json`
3. `prefill_from_resume(...)` merged with `profile_overrides` → `build_profile(...)` → save `profile.json`
4. `run_talent_check(profile, company, load_company_data())` → save `talent_check_result.json`
5. `match_skills(profile, jd_payload)` → save `skill_match_result.json`

Returns all five payloads in one dict. Also expose a `if __name__ == "__main__":` CLI so the whole flow can be proven from the terminal without the UI:

```bash
python pipeline.py --jd data/jds/microsoft_data_analyst.pdf \
                   --resume data/resumes/candidate_2.pdf \
                   --company "Microsoft Corporation"
```

## 9. `app.py` — Streamlit UI

Six tabs:

1. **JD Analytics** — file uploader, editable company/role fields, "Analyse JD" button, skills shown in a table grouped by category, raw JSON in an expander.
2. **Resume Parsing** — file uploader, "Parse Resume" button, extracted skills table + structured sections.
3. **Profile Builder** — form pre-filled from resume output if present. Text inputs for name, email, education. Multi-line text areas (one item per line) for hackathons, internships, certifications, preferred roles. A skills editor via `st.data_editor`. "Save Profile" button.
4. **Talent Check** — company dropdown (all ~98, defaulting to Microsoft), "Run Talent Check" button. Show `readiness_score` in `st.metric` with the verdict, then a horizontal bar chart of required vs candidate level for all 12 categories, then a table with the gap column. Highlight `top_gaps`.
5. **Skill Matching** — requires `jd_skills.json` and `profile.json`. Show `match_score`, matched list, and the missing-skills list rendered prominently.
6. **Full Pipeline** — pick a JD, a resume, and a company; one button runs everything and renders all five results stacked. **This tab is the demo.**

UI rules:
- Every tab must show a clear, non-technical message if its input file is missing: *"Run Resume Parsing first, or upload a profile."* Never a stack trace.
- Persist state in `st.session_state` so switching tabs never loses work.
- Every result panel has a "Download JSON" button.

Run with `streamlit run app.py`.

## 11. Correctness requirements

The build is not finished until all of these hold:

1. Every `category_code` written anywhere is a member of `ALL_CODES`. No free-text categories.
2. Talent Check scores **visibly differ** across the four sample candidates for the same company. A constant score means the level estimator is broken.
3. Skill Match scores visibly differ across different JDs for the same candidate.
4. The full pipeline runs end to end for at least one Google, one Microsoft, and one Oracle combination.
5. No module raises an unhandled exception on a malformed or missing input — every failure path returns a structured result or a readable message.

## 14. Notes for whoever builds this

- Write `contract.py` first and import from it everywhere. Duplicated category lists are the number one source of integration failure.
- Never let a module read or write a file. Only `storage.py` does.
- Prefer a boring deterministic result over a clever fragile one. A keyword extractor that always works beats an LLM extractor that fails during the demo.
- Add `print()` progress lines in `pipeline.py`. When something breaks under time pressure you need to see which of the five stages it broke in.
